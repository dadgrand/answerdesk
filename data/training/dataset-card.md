# Dataset card — query-rewriter pairs (t26)

**Name:** `answerdesk-rewriter-pairs` · **version:** 1.0.0 · **license:** CC0-1.0 (same as the
synthetic corpus it is derived from) · **owner:** t26 (llm-engineer).

## What it is

Noisy → clean query pairs for training a small instruction-tuned model to normalise
customer-support messages into a retrieval query. One row per pair:

```json
{"pair_id": "c-syn-ky-0002-q1", "locale": "ky", "category": "noisy_freeform",
 "style": "telegraphic", "source": "corpus_noisy",
 "noisy": "кредит кантип алуу", "clean": "Кредитке арызды кантип берем?",
 "doc_id": "syn-ky-0012", "answerable": true, "split": "train"}
```

`noisy` is what the customer typed, `clean` is the query the corpus generator wrote for the
same document (the reference the retriever was validated against). `source` is one of
`corpus_noisy` (a noisy category of the frozen corpus), `corpus_clean` (a clean question used
as an identity example, so the adapter does not rewrite already-clean input) or `perturbation`
(a deterministic mangling of a clean question, generated by this task).

## Construction rules (all enforced by code and tests)

1. **Categories excluded:** `pii`, `injection`, `unanswerable` — the first for privacy, the
   second because adversarial content is not a rewrite target, the third because an unanswerable
   message has no clean query to produce.
2. **Dedup:** exact duplicate `(noisy, clean)` pairs are collapsed; near-duplicates (4-gram
   Jaccard ≥ 0.97) are collapsed only for synthetic perturbations — the corpus legitimately
   repeats one archetype question across documents, and those repeats are kept.
3. **PII audit:** every pair is scanned with `answerdesk.policy.pii.detect`. 86 rows were
   excluded (mostly `identifier`-category rows where a long numeric identifier such as
   `ORD-2026-10314` trips the phone rule — a known false positive of that detector, reported
   upstream). The excluded ids are listed in `stats.json`.
4. **Splits are frozen and disjoint by construction:** each text (clean *and* noisy) is bound to
   one split via `sha256(salt:normalise(text))`; documents are then bound to their majority
   split and minority pairs are dropped (160 rows). The result: no clean or noisy string appears
   in two splits, and no document straddles a split. `tests/unit/rewrite/test_dataset.py`
   asserts both properties on the committed file.
5. **Determinism:** the builder is pure Python with a fixed seed; the hash of the committed
   pairs is `stats.json:hash` and the split assignment is recorded in `splits.json`.

## Known limitations

* **Fully synthetic.** The clean targets are generator-written sentences, not human phrasings;
  the noisy rows imitate telegraphic/typo/transliterated styles but no native speaker validated
  them. Uplift on this data is evidence that the pipeline works, not a claim about production.
* **Low-resource languages.** tg/ky/uz coverage is a few hundred pairs each; the adapter will be
  weakest exactly where the product needs it most.
* **Style imbalance.** Clean identity pairs outnumber transliterated ones 13:1; a production
  dataset needs more transliteration and code-switching.
* **No negative examples.** The pairs never say "this message needs no rewrite", so the adapter
  is trained purely by demonstration.
* **Identifier rows are underrepresented** because the PII audit removed them (see rule 3).
