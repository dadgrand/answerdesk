# Contributing to answerdesk

Thanks for taking the time. This project is a **reproducible reference implementation**, so the
contribution rules are slightly stricter than usual: a change is only done when it is measured, when
its behaviour is traceable to a requirement, and when the offline gate stays green.

## Ground rules

1. **Offline first.** Every test, default path and CI job must run with no network, no API key, no
   GPU and no Docker. An autouse fixture in `tests/conftest.py` fails any test that opens a socket;
   do not weaken it.
2. **No secrets, no private data.** Never commit keys, tokens, customer text, employer or bank code,
   or real personal data. Synthetic identifiers only (`example.com`, RFC 5737 addresses, documented
   test card numbers). Secrets live in `.secrets/` or the environment, never in the repo.
3. **Requirements are the contract.** Behaviour changes cite a requirement ID from
   [`docs/requirements.md`](docs/requirements.md) (`FR-…`, `NFR-…`, `INV-…`). If the requirement is
   wrong, amend it through change control (see that document's §18) instead of diverging quietly.
4. **Numbers are earned.** No hand-written metric in a document or README. Numbers come from
   artifacts under `reports/` and are generated by `scripts/build-results.py`; a judged metric without
   a κ caveat is a defect. Negative results are published, not deleted.
5. **Do not change module code in a docs task.** Docs and code move in separate PRs so review stays
   possible.

## Getting set up

```bash
uv sync --extra dev                 # light: no torch, no service deps
uv run pytest -q                    # the whole offline suite
uv run ruff check src tests && uv run ruff format --check src tests
uv run mypy src/answerdesk
pwsh -File scripts/ci-offline.ps1   # the same gate CI runs, one command
```

Console work additionally needs Node 20+:

```bash
cd web && npm ci && npm run test && npm run build
```

On Windows machines with a system proxy, prefix network-less commands with `$env:NO_PROXY='*'`
(`httpx` reads the Windows proxy settings and cannot drive a `socks4://` URL).

## What to send

- **Bug report** — use the issue template. Include the command, the observed output, and the
  requirement or invariant you believe is violated.
- **Feature or behaviour change** — open an issue first. If it changes a contract
  (`src/answerdesk/contracts.py`), a config key, a CLI flag, a metric definition or a threshold, it
  needs an ADR addition in [`docs/design-decisions.md`](docs/design-decisions.md) and a
  requirement amendment.
- **Evaluation change** — any change to datasets, splits, metrics or the judge needs its provenance
  hash updated and a fresh `docs/results.md` build; do not edit result tables by hand.

## Pull request checklist

- [ ] The change names the requirement ID(s) it implements or amends.
- [ ] `# AT-xxx-nn` traceability markers exist for the new behaviour (see the matrix in
      `docs/requirements.md` §16). `scripts/check-traceability.py` must keep passing.
- [ ] `uv run pytest -q` passes offline; `ruff` and `mypy` are clean.
- [ ] New behaviour has a test that fails when the behaviour is removed (mutation-style spot check).
- [ ] Docs are updated in the same PR: the module doc, the ADR if a decision changed, and README if a
      public command or claim changed.
- [ ] No new runtime dependency without a licence entry (MIT/BSD/Apache-2.0/ISC/PSF; unmodified
      MPL-2.0 only). Heavy dependencies go behind an extra.
- [ ] No secret, no private data, no fabricated number.

## Style

- Python 3.11+, fully typed (`disallow_untyped_defs`), `ruff` with line length 100, docstrings on
  public functions that explain *why*.
- Cross-module types come from `answerdesk.contracts` (pydantic models with `extra="forbid"`), never
  ad-hoc dicts. Every pluggable component implements one of its `Protocol`s.
- Commits: imperative subject ≤ 72 characters, body explains the measurement or the failure, and
  references the requirement/task id. Example:
  `feat(cache): guard on document hash before a hit (FR-CAC-03)`.
- Tests: one file per behaviour area, no network, no sleeps over 50 ms, no reliance on wall-clock
  ordering. Prefer the deterministic doubles in `answerdesk.testing`.

## Honesty rules (they are enforced in review)

1. A claim that a guard, metric or threshold works needs the artifact that shows it.
2. If a measurement contradicts a design assumption, the document records the contradiction and the
   roadmap decides what happens next — the number is not re-cut to fit.
3. Anything not measured is labelled as an assumption, in the same sentence.
4. Do not describe the system as "calibrated", "risk-controlled" or "production-ready" beyond what
   `docs/results.md` demonstrates. Today that means: no risk-control claim.
